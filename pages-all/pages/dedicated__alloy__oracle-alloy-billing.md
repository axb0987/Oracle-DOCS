# Oracle Alloy Billing

Billing operations are performed at the billing-account level. A billing account captures the subscriber values used for billing and exposes the billing dates that control execution. These dates include the last billed date, billing cutoff date, billing cycle, and next billing run date. Billing cycles can be configured on a recurring cadence, such as monthly, quarterly, or annually, based on the commercial terms for the subscription.

When billing must be paused for an account, place the account on billing hold. Billing holds are used for customer-request investigations, failure-to-pay conditions, or fraud review. Add comments to capture the reason for the hold. When you remove a billing hold, the workflow can present the option to run billing immediately or wait until the next scheduled run.

Billing runs typically run on the billing-cycle schedule. You can also create billing runs manually when operational correction is required. Manual runs support regular billing by cycle or on-demand billing by account. Use simulation mode to preview the run before execution. Existing runs can be paused or canceled when the run state supports that action.

Billing history provides downloadable pre-tax billing documents in CSV format so that you can review invoiced usage for a billing account. For commitment-based subscriptions, the document typically shows a base-rate line item and separate overage line items by SKU. For pay-as-you-go subscriptions, the document lists the consumed SKUs that were billed during the run.
