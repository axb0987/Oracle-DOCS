# Creating Virtual Nodes with Updated Properties

Find out about the different ways to update virtual node properties using Kubernetes Engine (OKE).

You use Kubernetes Engine to set virtual node properties in a cluster. When those property requirements change, you can either add a new virtual node pool with the required properties (see[Adding Node Pools to Scale Up Clusters](https://docs.oracle.com/en-us/iaas/Content/ContEng/Tasks/contengaddingnodepools_topic.htm)), or modify an existing virtual node pool (see[Modifying Node Pool and Worker Node Properties](https://docs.oracle.com/en-us/iaas/Content/ContEng/Tasks/contengmodifyingnodepool.htm)). When you modify an existing virtual node pool, the changes apply only to new virtual nodes. Existing virtual nodes keep their previous properties until they are replaced.

For example, you might want all the virtual nodes in a virtual node pool to have a new Kubernetes label. You can add a new virtual node pool with the Kubernetes label property set to the label key and value. Or you can modify an existing virtual node pool and set the Kubernetes label property as required.

Note that if you simply change the existing virtual node pool's Kubernetes label property to a new key and value, only new virtual nodes that start in the virtual node pool will have the new label. Existing virtual nodes continue to have previous Kubernetes labels (if specified). However, you can change properties of virtual nodes (such as Kubernetes label ) in the following ways:
- Perform an 'in-place' update, by updating virtual node pool properties and then cycling the nodes. First, you modify the existing virtual node pool's virtual node properties. Then, you cycle the virtual nodes in the virtual node pool. When you cycle the virtual nodes, Kubernetes Engine automatically cordons, drains, and terminates existing virtual nodes, and creates new virtual nodes. When new virtual nodes are started in the existing virtual node pool, they have the updated properties you specified. For more information, see[Performing an In-Place Virtual Node Update by Cycling Virtual Nodes in an Existing Virtual Node Pool](https://docs.oracle.com/en-us/iaas/Content/ContEng/Tasks/contengcreatingvirtualnodesupdatedprops_topic-Performing_an_InPlace_Virtual_Node_Update_By_Cycling_an_Existing_Node_Pool.htm).
- Perform an 'in-place' update, by reducing the virtual node pool's Node count property to zero, updating virtual node properties, and then increasing the Node count property . First, you reduce the existing virtual node pool's Node count property to zero and save the change. Kubernetes Engine cordons, drains, and terminates existing virtual nodes in the original virtual node pool to prevent new pods from starting, and to delete existing pods. Then you update the existing node pool's virtual node properties as required. Finally, you increase the virtual node pool's Node count property to the required size. When new virtual nodes are started in the existing virtual node pool, they have the updated properties you specified. See[Performing an In-Place Virtual Node Update by Reducing Node Count to Zero, Updating Node Properties, and then Increasing Node Count](https://docs.oracle.com/en-us/iaas/Content/ContEng/Tasks/contengcreatingvirtualnodesupdatedprops_topic-Performing_an_InPlace_Virtual_Node_Update_By_Updating_an_Existing_Node_Pool.htm).
- Perform an 'out-of-place' update, by replacing the original virtual node pool with a new virtual node pool. First, you create a new virtual node pool and set virtual node properties as required. Then, you delete the original virtual node pool. Kubernetes Engine cordons, drains, and terminates existing virtual nodes in the original virtual node pool to prevent new pods from starting, and to delete existing pods. When new virtual nodes are started in the new virtual node pool, they have the properties you specified. See[Performing an Out-of-Place Virtual Node Update by Replacing an Existing Virtual Node Pool with a New Virtual Node Pool](https://docs.oracle.com/en-us/iaas/Content/ContEng/Tasks/contengcreatingvirtualnodesupdatedprops_topic-Performing_an_OutofPlace_Virtual_Node_Update_by_Replacing_an_Existing_Node_Pool_with_a_New_Node_Pool.htm).

Note that in all cases:
- Special considerations apply when updating the Kubernetes version running on virtual nodes in a virtual node pool. Instead of following the instructions in this section, follow the instructions in[Upgrading Virtual Nodes to a Newer Kubernetes Version](https://docs.oracle.com/en-us/iaas/Content/ContEng/Tasks/contengupgradingvirtualnodes.htm).
